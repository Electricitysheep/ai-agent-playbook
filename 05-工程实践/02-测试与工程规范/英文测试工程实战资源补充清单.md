---

## 总览:为什么 AI 应用工程师必须写测试

测试不是"找 bug",而是**工程素养的底线信号**。AI 项目的 LLM 调用天然不稳定(响应非确定、慢、贵、可能超时),如果不写测试:
- 你的简历上写"模型准确率 95%"但没有 CI 流水线验证 → 面试官立刻怀疑
- 任何 prompt 改动、模型升级都会无声引入退化
- 微调实验的回归(regression)无法自动捕捉

下面这套组合:**pytest + pytest-cov + pytest-mock + Hypothesis** 是 2025-2026 年 Python AI 项目的标准测试栈。

## 1. pytest 基础(必学)

### 资源 1: [pytest 官方文档](https://docs.pytest.org/)
- **平台/作者**: pytest-dev 社区
- **推荐理由**: Python 测试事实标准。2025 年 v8.x 已稳定覆盖 fixtures、parametrize、plugins、async 测试。AI 应用工程师写的每一个 LLM 调用封装都必须有测试。
- **使用方式**: 完成 Getting Started + "How to use fixtures" + "Parametrizing tests" 三个章节。配合自己项目写第一个 `test_*.py`。
- **优先级**: P0

### 资源 2: [Real Python — pytest 入门指南](https://realpython.com/pytest-python-testing/)
- **平台/作者**: Real Python
- **推荐理由**: 比官方文档更循序渐进,适合"第一次接触 pytest"的开发者。涵盖 assert 重写、fixture scope、test discovery 机制。
- **使用方式**: 周末通读 1 次,然后边写项目边查。
- **优先级**: P0

### 资源 3: [Pytest-with-Eric — pytest TDD Example 仓库](https://github.com/Pytest-with-Eric/pytest-tdd-example)
- **平台/作者**: Eric (Pytest 实战博主)
- **推荐理由**: 一个完整展示 Red-Green-Refactor 流程的示例仓库,包含 fixtures、mocking、parametrize 的实战用法。比官方文档更贴近真实项目结构。
- **使用方式**: Clone 仓库 → 按 README 步骤执行 TDD 循环 → 把模式迁移到自己的 Agent 项目。
- **优先级**: P1

## 2. Mocking(LLM 调用测试的核心)

### 资源 1: [unittest.mock 官方指南](https://docs.python.org/3/library/unittest.mock.html)
- **平台/作者**: Python 官方
- **推荐理由**: AI 应用测试的核心难点是 LLM 调用不可控、慢、贵。Mock 是单元测试隔离外部依赖的唯一手段。`Mock`、`patch`、`side_effect` 必须掌握。
- **使用方式**: 在测试中 `patch("openai.ChatCompletion.create")` 模拟 LLM 响应。
- **优先级**: P0

### 资源 2: [pytest-mock 官方文档](https://pytest-mock.readthedocs.io/)
- **平台/作者**: pytest-mock 维护者
- **推荐理由**: pytest-mock 提供 `mocker` fixture,语法比 `unittest.mock` 更简洁。2025 年广泛用于 FastAPI 项目。
- **使用方式**: 写一个 `def test_llm_call(mocker): mocker.patch("...openai...")` 体验。
- **优先级**: P0

### 资源 3: [freeCodeCamp — How to mock API calls in pytest](https://www.freecodecamp.org/news/tag/tdd/)
- **平台/作者**: freeCodeCamp 社区
- **推荐理由**: 大量免费实战文章,覆盖 "mock OpenAI/Anthropic API in tests"、"如何用 VCR.py 录制 HTTP 流量"等真实场景。
- **使用方式**: 搜索 "pytest mock OpenAI" 等关键词,按需阅读。
- **优先级**: P1

### 资源 4: [VCR.py](https://vcrpy.readthedocs.io/)
- **平台/作者**: VCR.py 社区
- **推荐理由**: 录制一次真实的 LLM API 响应(比如 "What is 2+2?")存为 cassette,之后测试都重放这个响应。比 mock 更真实,适合**集成测试**。
- **使用方式**: `pip install vcrpy` → 用 `@vcr.use_cassette` 装饰测试。
- **优先级**: P2

## 3. 覆盖率与质量

### 资源 1: [Coverage.py + pytest-cov](https://coverage.readthedocs.io/)
- **平台/作者**: Ned Batchelder / pytest-dev
- **推荐理由**: 测试覆盖率是代码质量的底线指标。pytest-cov 一键生成 HTML 报告,能精确定位哪些 LLM 分支逻辑没被覆盖。
- **使用方式**: `pip install pytest-cov` → `pytest --cov=src --cov-report=html` → 把覆盖率门槛写进 CI(80% 是常见起点)。
- **优先级**: P0

### 资源 2: [SonarQube / SonarCloud](https://www.sonarsource.com/products/sonarcloud/)
- **平台/作者**: SonarSource
- **推荐理由**: 持续检查代码 smell、bug、安全漏洞。2025 年免费版对开源项目开放,可作为 GitHub Action 集成。
- **使用方式**: 在 GitHub 仓库开通 SonarCloud → 写 `.sonarcloud.properties` 配置。
- **优先级**: P2

### 资源 3: [pre-commit + ruff + black](https://pre-commit.com/)
- **平台/作者**: pre-commit 框架 + Astral(ruff 开发者)
- **推荐理由**: 提交前自动运行 linter/formatter。ruff 是 2024-2025 年最快的 Python linter,速度是 flake8 的 50×。**面试讲"我用 pre-commit + ruff 保证代码风格一致"是工程素养加分项**。
- **使用方式**: 写 `.pre-commit-config.yaml`,配置 ruff + black + mypy。
- **优先级**: P1

## 4. LLM 评估专项(AI 项目独有)

### 资源 1: [DeepEval](https://github.com/confident-ai/deepeval)
- **平台/作者**: Confident AI (1.5K+ stars, 2025 年快速成长)
- **推荐理由**: LLM 应用的"pytest"。内置 G-Eval、Hallucination、Bias、Toxicity 等 20+ 评估指标,可对 RAG、Agent、Chatbot 做回归测试。
- **使用方式**: 看 [Quickstart](https://docs.confident-ai.com/),跑一个 `deepeval test run`。
- **优先级**: P0(AI 应用项目 P0)

### 资源 2: [RAGAS](https://github.com/explodinggradients/ragas)
- **平台/作者**: Exploding Gradients (3K+ stars)
- **推荐理由**: RAG 系统评估的事实标准。四个核心指标:Context Relevance、Answer Relevancy、Faithfulness、Context Recall。是转码方案 4.2 提到"RAG 全链路评测"的具体工具。
- **使用方式**: 跑通 `ragas.evaluate()` 评估自己的 RAG pipeline。
- **优先级**: P0(RAG 项目 P0)

### 资源 3: [Promptfoo](https://github.com/promptfoo/promptfoo)
- **平台/作者**: promptfoo 团队 (3K+ stars)
- **推荐理由**: Prompt 版本管理与 A/B 测试 CLI。可以用 YAML 写"同一问题多种 prompt",自动评分并对比。**生产级 Agent 必备**。
- **使用方式**: `npx promptfoo init` → 写 `promptfooconfig.yaml` → `promptfoo eval`。
- **优先级**: P1

### 资源 4: [Braintrust](https://github.com/braintrustdata/braintrust)
- **平台/作者**: Braintrust (1.5K+ stars)
- **推荐理由**: LLM 应用的可观测性平台 + 评估框架。类似 "LLM 版的 Datadog"。本地开源版可对接 Postgres。
- **使用方式**: 参考 README,接入 OpenAI/Anthropic SDK。
- **优先级**: P2

## 5. Property-based Testing(高级)

### 资源 1: [Hypothesis](https://hypothesis.readthedocs.io/)
- **平台/作者**: Hypothesis 团队
- **推荐理由**: "自动生成边界用例"——给一个函数,自动找出会让它 crash 的输入。2025 年已支持 pytest 集成。对 RAG chunking、prompt parser 之类的"输入千变万化"的代码尤其有用。
- **使用方式**: `pip install hypothesis` → `@given(texts())` 装饰器。
- **优先级**: P2

### 资源 2: [Hypothesis Quickstart Guide](https://hypothesis.readthedocs.io/en/latest/quickstart.html)
- **平台/作者**: Hypothesis 团队
- **推荐理由**: 30 分钟入门,讲 `given`、`strategies`、`assume`、`example` 四大基本概念。
- **使用方式**: 周末精读,然后挑一个项目中的解析函数试试。
- **优先级**: P2

## 6. CI/CD 集成(让测试真正起作用)

### 资源 1: [GitHub Actions for Python](https://docs.github.com/en/actions/automating-builds-and-tests/building-and-testing-python)
- **平台/作者**: GitHub 官方
- **推荐理由**: 把 pytest + coverage 接入 PR 检查。"每次 push 都自动跑测试 + 生成覆盖率徽章"是简历项目必备。
- **使用方式**: `.github/workflows/test.yml` 配 `actions/setup-python@v5` + `pytest`。
- **优先级**: P0

### 资源 2: [Codecov / Coveralls](https://about.codecov.io/)
- **平台/作者**: Codecov
- **推荐理由**: 自动把覆盖率报告生成 README 徽章。免费版对开源项目足够。
- **使用方式**: 在 GitHub Actions 里 `codecov/codecov-action@v4`。
- **优先级**: P1
