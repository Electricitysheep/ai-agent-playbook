## 5.1 是什么（30 秒版）

生产系统与合规架构 = 把"研究出来的策略"变成"能实盘、能审计、能活过监管"的系统。
三条主线：
1. **实时信号链路**：盘中数据 → 因子 → 信号 → 订单的端到端时延与更新频率设计；
2. **独立风控叠加层**：风控独立于信号层，强制行业/因子/头寸限制——**绝不让单个 LLM
   幻觉直接 sizing 进组合**（2026 年最重要的工程原则之一）；
3. **合规与安全**：算法备案、穿透式风控、《金融机构 AI 应用管理指引》落地、AI 安全防线
   （vishing/prompt injection）。
核心判断：**"能回测"和"能生产"是两种能力**——生产要回答时延、审计、故障切换、监管报告。

## 5.2 为什么重要（行业证据）

- **独立风控是行业共识**：主报告 §6——"执行与风控层独立于 AI 信号层，强制行业/因子/
  头寸限制，绝不让单个 LLM 幻觉直接 sizing 进组合"（AgentPit，2026-04）；证监会
  《金融机构 AI 应用管理指引》（2026）要求**算法备案与穿透式风控**成为实盘 AI 交易
  系统核心门槛。
- **中国监管落地（金发〔2026〕8 号，2026-06-18，一手）**：金融监管总局《关于银行业保险业
  人工智能安全开发应用的指导意见》8 章 32 条——虽面向银保，但确立的框架券商/私募
  直接对标（diaifu 解读，2026）：
  - **四大原则**：AI 应用合规、透明、可信赖；**全生命周期管理**（需求→数据→训练→
    部署→迭代→退出）；
  - **风险分类分级**：涉及资金交易/风险管理/与客户利益直接相关的生成式 AI = 高风险，
    须风险管理委员会批准 + 人工监督干预；
  - **可解释性红线**：第 22 条"可解释性不足的 AI 在高风险场景仅能作为辅助工具，
    应由人工最终决策"——**黑箱模型不能独立做金融决策**，须留原始数据/推理路径/
    阈值触发记录，定期独立算法审计；
  - **外部模型准入**：外部生成式 AI 须经网信部门备案 + 名单制管理；
  - **安全防线**（第 25 条）：防范提示词注入、思维链注入、多模态攻击、上下文污染、
    记忆污染、身份越权、工具滥用、运行失控。
- **AI 攻击是运营风险**（2026-08 一手）：Point72/Citadel/Millennium/Two Sigma 遭
  **AI 语音克隆 vishing 攻击**（冒充 IT/同事要凭证），Two Sigma 确认成功拦截、
  Point72 调查中；归因 UNC6671 勒索组织（BleepingComputer，2026-08-06）；
  FINRA 2026-03 上线 Financial Intelligence Fusion Center 威胁情报共享门户；
  安全专家："AI 把定向攻击成本降低到可以同时打 1000 家"（Align Managed Services）。
- **国际参照**：EU AI Act 高风险义务 2026-08-02 起适用（金融高风险罚款最高 €3500 万
  或全球营业额 7%）；FCA 2025-08 算法交易多机构审查要求整改治理/测试/市场滥用监控；
  英国央行实测 TSFM 数据也显示"实时评估比文献乐观结论更弱"——生产环境的诚实评估。

## 5.3 怎么做（方法步骤 + 架构 + 踩坑点）

### 生产架构五层（面试画图）

```
[数据层] L2/快照/逐笔 → 清洗 → PIT 数据库（主题 05/10）
[因子层] 因子实时计算（增量）+ 因子库（parquet/mmap）
[信号层] 模型推理（LLM 分析 / ML 因子合成）→ 信号
   ↓ 独立风控叠加层（不看信号内容，只看风险约束）
[风控层] 头寸限制 / 行业暴露 / 因子暴露 / 换手限制 / 单笔限额 / 熔断
   ↓ 通过后才允许下单
[执行层] RL 执行 / 智能拆单（主题 03）→ 报单 → 成交回报
[合规层] 算法备案 / 交易日志 / 异常报告 / 审计轨迹（贯穿全部）
```

### 独立风控叠加层设计（核心工程原则）

```python
# 风控层与信号层完全解耦：风控只看约束，不看"信号理由"
def risk_gate(signal, portfolio, constraints):
    """返回 (通过?, 拒绝原因)。信号想下多大不重要，约束说了算。"""
    checks = [
        (portfolio.position + signal.size <= constraints["max_position"], "头寸超限"),
        (portfolio.industry_exposure + signal.industry <= constraints["max_industry"], "行业暴露超限"),
        (portfolio.factor_exposure + signal.factor <= constraints["max_factor"], "因子暴露超限"),
        (signal.size * signal.price <= constraints["max_trade_value"], "单笔金额超限"),
        (portfolio.daily_turnover + signal.turnover <= constraints["max_turnover"], "换手超限"),
        (not signal.risk_flag, "风控标记"),
    ]
    for ok, reason in checks:
        if not ok:
            return False, reason
    return True, ""
```

### 实时信号链路（盘中更新频率设计）

- **频率决策矩阵**：信号更新频率 × 数据延迟 × 成本预算——
  分钟级因子盘中 1-5 分钟更新、日频因子盘后更新、LLM 分析事件驱动（新闻/电话会触发）；
- **关键：信号与执行解耦**——信号生成是"研究节奏"，执行是"市场节奏"（RL 执行）；
- 时延预算：数据摄入→因子→信号→风控→订单，每段有 SLO（如总时延 <1s 用于中频）。

### 合规落地清单（面试可直接背）

1. **算法备案**：程序化交易策略报备（报告义务）+ AI 模型备案（外部模型网信备案）；
2. **穿透式风控**：AI 信号不得绕过风控直连下单；风控规则可审计、可追溯；
3. **可解释性**：高风险 AI 决策保留推理路径/阈值触发记录；人工复核节点；
4. **日志留存**：全流程关键操作日志，保存期限不低于业务存续期（金发 8 号第 21 条）；
5. **AI 安全**：vishing 应对（语音克隆识别、凭证重置双人复核）、prompt injection 防线
   （输入过滤/权限隔离/输出验证）、供应链投毒排查（开源组件台账）；
6. **上线四步**：回测 → 模拟盘 → 小仓实盘 → 全量（主报告 §9，不可跳过）。

### 踩坑点（面试高频）

1. **风控被"优化"掉**：研究阶段为了"更好的回测"把风控放宽，上线后回撤失控——
   风控必须独立、研究不可触碰；
2. **LLM 直接 sizing**：让 LLM 输出"买 5000 万"而不经风控——幻觉直接进组合
   （主报告红线）；正确做法：LLM 输出"方向+理由"，头寸由风控/组合优化决定；
3. **日志不全 = 监管被动**：出事说不出"为什么"（哪个因子触发、哪个阈值）——
   金发 8 号第 22 条要求完整保留推理路径；
4. **外部模型"拿来就用"**：未备案模型直接接入生产（金发 8 号第 5 条红线）；
5. **AI 攻击面**：vishing 语音克隆（2026-08 实测案例）、prompt injection、模型投毒——
   安全是生产系统的"第 0 层"。

**可能的追问与应答**：
- Q：独立风控具体怎么保证"独立"？
  A：三层独立：**组织独立**（风控团队不向投研汇报）、**系统独立**（风控服务单独部署，
  信号层无法绕开）、**逻辑独立**（风控只看约束不看信号理由，参数由风控委员会定，
  研究员不可触碰）。上线四步中模拟盘就是验证风控独立性的。
- Q：LLM 怎么接入生产而不让幻觉进组合？
  A：LLM 定位为"分析师"而非"决策者"：输出方向+理由（结构化），头寸大小由
  组合优化/风控决定；LLM 信号也要过回测纪律（IC/DSR，主题 01/07）才能进因子库；
  生产上对 LLM 输出做 schema 校验 + 风险标记（如"证据不足"强制降权）。
- Q：算法备案/穿透式风控的技术含义？
  A：备案 = 策略逻辑与参数报告监管（程序化交易报备、AI 模型备案）；穿透式 =
  AI 信号→风控→下单全链路可审计，监管可追溯任一交易是哪个信号/模型/参数触发的；
  工程上就是：完整日志 + 推理路径留存 + 阈值触发记录（金发 8 号第 22 条）。
- Q：AI 安全防线具体做什么？
  A：三类：**vishing**（语音克隆识别、凭证重置必须双人复核+本人线下确认——2026-08
  实证案例）；**prompt injection**（输入过滤、系统提示与用户输入隔离、输出校验、
  工具调用白名单、权限最小化）；**模型供应链**（开源组件台账、权重完整性校验、
  防投毒）。金发 8 号第 25 条已明确要求防范这些威胁。
