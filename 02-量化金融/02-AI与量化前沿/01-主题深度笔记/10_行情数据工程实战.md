## 5.1 是什么（30 秒版）

行情数据工程 = 把"分钟级/逐笔行情 → 可回测因子"的管道工程化：数据摄入（L2/快照/逐笔 →
统一 OHLCV+量）、跨引擎对齐（Pandas/Polars 双引擎 0 误差验证）、增量计算（避免全量重算）、
因子存储（parquet/内存映射）。**核心纪律**：杜绝未来函数（时空坐标系锁定）、确定性排序
（并发 tie-breaking）、垃圾进垃圾出（统一 NaN/Null/Inf 标准）。这是所有 AI 量化上层
（因子、模型、回测）的地基——用户实习"7462 万行分钟级行情 + 双引擎对齐 + 6→54 因子 +
5-10 倍加速"就是这个主题的实战版。

## 5.2 为什么重要（行业证据）

- **数据是 AI 量化的地基**：主报告五环节第一环就是"数据"——LLM 管非结构化摄入，
  但结构化行情管道的质量决定上层一切；Qlib 的 point-in-time 数据库（主题 05）本质
  就是"数据工程纪律"的平台化。
- **生产系统的事实标准**：parquet 列式存储 + zstd 压缩、Polars/duckdb 加速、
  增量计算框架是 2025-2026 量化数据工程的主流栈（Qlib Arctic Provider、polars 生态）。
- **实习价值锚点**：用户简历的"7462 万行/5-10 倍加速/54 因子"是券商金工与量化私募
  面试的 A 级故事（03_量化金融/README.md 明确标注）——本主题把它"理论化、可复现化"，
  面试时既能讲工程又能讲原理。
- **错误代价**：跨日界未来函数（实习"时空坐标系锁定"）、并发乱序（tie-breaking）、
  脏数据污染（NaN/Inf）——任何一个都会让上层因子/模型结论失真（主题 07 的
  回测纪律从数据层就开始）。

## 5.3 怎么做（方法步骤 + 关键代码 + 踩坑点）

### 标准管道（四层）

```
[摄入] L2/快照/逐笔 → 清洗（统一 NaN/Null/Inf、去重、复权）
  → 标准化为 date×symbol 面板（或多级索引分钟面板）
[对齐] Pandas 与 Polars 双引擎 SBS（Side-by-Side）验证——0 误差是硬标准
[计算] 因子计算：增量框架（只算新数据，复用历史）+ 确定性排序 + round(8) 截断
[存储] parquet（列式 + zstd 压缩 + 分区）+ 内存映射（mmap）支持大面板热读
```

### 关键代码模式（本实验已验证）

```python
# 1) 双引擎对齐：同一因子必须数学定义一致（按日分组 vs 跨日滚动是不同定义！）
pandas: day_vwap = vwap.groupby(date).transform("mean")       # 按日
polars: vwap.mean().over(["symbol", dt.truncate("1d")])       # 按日 ← 必须一致
# 2) 确定性：round(8) 截断 + sort_values 强制定序（防并发 tie-breaking 乱序）
# 3) 增量：只对新数据窗计算（实习提升 10 倍+ 的关键）
# 4) 存储：df.to_parquet(path, compression="zstd") + read_parquet(columns=[...])
```

### 踩坑点（本实验真实踩到，面试直接讲）

1. **MultiIndex 非唯一索引崩溃**：yfinance 分钟数据有重复时间戳（盘前盘后/跨日界），
   pandas setitem 时 `reindex` 抛 `Index._join_level on non-unique index`——
   修复：加载时 `drop_duplicates` + 因子计算用 dict 构造 DataFrame（位置对齐）；
2. **双引擎定义漂移**：vwap_dev 若 pandas 按日分组、polars 用跨日滚动，误差 5.6e-3——
   对齐方法论的核心是"定义先行，实现后验"；
3. **诚实报告加速比**：本机实测 3.9x（3 个简单因子），实习 5-10x 来自 54 因子 +
   惰性求值 + 更大规模——面试讲"我复现过、加速比随复杂度上升"。
4. **跨日界对齐**：分钟级动量/波动率绝不能把昨日收盘和今日开盘混进同一窗口
   （实习"时空坐标系锁定"）——工程上按 (symbol, date) 分组重置窗口。

**可能的追问与应答**：
- Q：双引擎对齐为什么是 0 误差不是"近似"？
  A：因为同一因子的数学定义必须完全一致（如"当日 VWAP"必须两边都按日分组），
  计算实现不同（pandas groupby vs polars over）但语义相同；再用 round(8) 截断
  消除浮点噪声。若两边定义漂移（跨日滚动 vs 按日分组），误差立刻到 1e-3 量级——
  我实测踩过这个坑。
- Q：增量计算怎么保证正确性？
  A：增量 = 只对新窗口计算 + 复用历史结果，但**增量结果必须与全量重算做一致性校验**
  （在样本窗口内做一次全量 vs 增量对比，0 误差后才上线）——这是"算得快"的前提是
  "算得对"。
- Q：分钟级数据跨日界怎么处理？
  A：时空坐标系锁定：按 (symbol, date) 分组，动量/波动率的滚动窗口在每日开盘处重置，
  绝不把昨日收盘与今日开盘混进同一窗口；节假日用交易日历对齐。
- Q：为什么用 parquet 不用 CSV/数据库？
  A：列式存储天然适合"读部分列"（因子库常只需读 3-5 个因子）；zstd 压缩省 90% 空间；
  配合分区（按日期/股票）和内存映射可支持几十亿行面板热读。生产标准（Qlib Arctic
  也用类似思路）。
